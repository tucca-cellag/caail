# Community

CAAIL is curated by the [Tufts University Center for Cellular Agriculture (TUCCA)](https://cellularagriculture.tufts.edu/). The Slack workspace around it is open to anyone working on cell lines, media, bioreactors, or scaffolds, and to anyone developing the computational methods applied to them.

Discussion takes place in Slack. Changes to the library itself are made through GitHub.

## Where to go for what

| If you want to | Go to |
| --- | --- |
| Ask a question about either field | [Slack](#join-the-slack), in `#cell-ag-questions` or `#ai-questions` |
| Suggest a paper, tool, dataset, or other resource | [Slack](#join-the-slack), in `#feature-requests`, or [a GitHub issue](https://github.com/tucca-cellag/caail/issues/new/choose) |
| Report a broken link or a miscategorized entry | [Slack](#join-the-slack), in `#bug-reports`, or a GitHub issue |
| Propose a specific change yourself | [A pull request](./CONTRIBUTING.md) |
| Read the full text of a catalogued paper (core TUCCA members) | The [caail Zotero group library](https://www.zotero.org/groups/6549203/caail/library) |

Suggestions are accepted through either channel, and a GitHub account is not required. Slack carries less overhead and is the appropriate place to raise a resource whose fit you are uncertain about.

GitHub holds the durable record. A suggestion moves to an issue or a pull request once it is ready to become a change, which keeps the rationale attached to it. A maintainer will make that transfer on your behalf if you prefer.

The Zotero group library is a members-only working library rather than a contribution channel. It exists so that AI agents running on TUCCA members' machines can classify a paper from its methods section rather than its abstract.

## Community norms

Cellular agriculture and machine learning do not share a vocabulary. The same term frequently denotes different things in each field, and establishing which sense is meant is faster than proceeding on an assumed agreement.

- **Define terms that cross fields.** Few participants have equal depth in both domains. A request for clarification is not a sign of inexperience.
- **Report results with their conditions.** Give the metric, the dataset or system it was measured on, and the regime in which it holds. The same standard applies when disputing a result.
- **Separate findings from conjecture.** Hypotheses and preliminary observations are useful when identified as such.
- **Share your own work directly.** Preprints, papers, and tools are appropriate to post. Sustained promotional posting is not.

Those are conventions. The [Code of Conduct](./CODE_OF_CONDUCT.md) sets the requirements: respect for differing viewpoints and experiences, willingness to accept constructive feedback, and good-faith interpretation of others. Harassment, personal attacks, trolling, sexualized language, and publication of others' private information are grounds for removal.

It applies to the Slack workspace, the issue tracker, and code review, and to maintainers on the same terms as everyone else. Report a problem to <benjamin.bromberg@tufts.edu> or <jim.plotts@tufts.edu>. If a report concerns one of them, send it to the other; anyone who is the subject of a report is recused from handling it.
